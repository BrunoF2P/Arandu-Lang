# Arandu 0.1.0-rc.1 — relatório de promoção

**Estado:** preparação; nenhuma tag foi criada.  
**Canal:** primeira release candidate pública do SDK Arandu v0.1.

O PR de preparação deve ser mergeado e ficar integralmente verde antes da tag.
Depois, a tag anotada é criada sobre esse commit já presente na `main`:

```bash
git switch main
git pull --ff-only origin main
cargo run --locked -p xtask -- check-release-contract v0.1.0-rc.1
git tag -a v0.1.0-rc.1 -m "Arandu 0.1.0-rc.1"
git push origin v0.1.0-rc.1
```

Não use `--force`, não crie a tag na branch do PR e não publique manualmente
assets paralelos. O workflow serializado é a única autoridade de promoção.

## Escopo congelado

Esta RC entrega CLI, `arandu-lsp` e stdlib como uma unidade versionada para:

- Linux x86-64 glibc;
- macOS Apple Silicon;
- Windows x86-64 MSVC.

Não promove LLVM, ABI estável, cross-compilation, self-hosting, debugger,
macOS Intel nem outros targets. O backend C permanece experimental.

## Bloqueadores eliminados durante a preparação

- O cliente VS Code passou a exigir Node 20/VS Code 1.92 e o lockfile foi
  atualizado para `brace-expansion` 5.0.9, que corrige a vulnerabilidade e o
  bypass conhecidos nas versões anteriores.
- O Cranelift gravava literal `int` de payload de enum como 32 bits e o lia com
  largura de ponteiro. Os bytes superiores não inicializados tornavam guards de
  `match` dependentes do conteúdo do `malloc`. A tradução agora usa o tipo
  declarado da variante e uma regressão acima de 32 bits cobre o contrato.
- O smoke público baixa o sidecar exigido pelo instalador de cada host:
  BLAKE3 em Unix e SHA-256 em Windows.
